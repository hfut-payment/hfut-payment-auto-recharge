# 自动充值

为宣城校区的常规电费、空调电费、洗浴和校园网设置自动充值。每个项目可单独设置余额低到多少时补款、补多少，以及校园卡至少要留多少钱。

> [!IMPORTANT]
> **自动充值会实际扣款。** 启用前请逐项核对房间、手机号、充值金额与余额阈值。充值结果未确认时，先核对校方账单，再决定是否解除暂停。软件按现状提供，使用及核账责任以适用法律为准。

## 安装与启用

1. 确认手机宿主支持 HFP v2、校园费用充值权限和定时任务。先在宿主里配置宿舍或洗浴账号，并按提示保存支付密码。
2. 从 [Releases](../../releases) 下载 HFP，在宿主的插件管理里导入，查看并确认所需权限。
3. 从插件设置或费用详情的「更多服务」打开对应项目。填写余额阈值、每次充值金额和校园卡最低保留余额，核对预览后再启用。更换项目或升级规则格式后，需要重新确认授权。
4. 要停止某项自动充值，关闭对应规则。如果看到「充值结果未确认」，按页内提示先核对账单。

任务约每 15 分钟检查一次。电费只在北京时间 06:00 至 23:00 前自动充值。洗浴和校园网可全天检查，确认失败后至少等 1 小时才重试。充值金额和累计支出仍受宿主的支付校验约束。

## 从源码打包

需要 Node.js 22.2 或更新版本。本仓库含插件源码和打包脚本。

~~~sh
node scripts/pack.mjs --source hfp --key /path/to/private.pem --cert /path/to/certificate.pem
~~~

产物位于 dist。覆盖升级需使用原发布证书。使用其他签名构建的包，能否使用扣款能力取决于宿主信任策略。

## 发布新版本

更新 `hfp/manifest.json` 的 `version` 和 `revision`，提交改动。在 [Actions](../../actions/workflows/build-plugin.yml) 手动运行 `signed_candidate` 可以先验签和验证安装。审核通过后，在本地 `main` 分支给对应提交打标签，例如：

~~~sh
git tag -a v1.5.0-beta.4 -m "Release v1.5.0-beta.4"
git push --atomic origin main refs/tags/v1.5.0-beta.4
~~~

公开仓库的标签构建会在验签后把 HFP 和校验文件发布到 [Releases](../../releases)。带 `-beta` 后缀的版本标记为预发行。
