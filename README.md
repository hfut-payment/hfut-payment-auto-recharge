# 自动充值插件（Beta）

这是一个面向宣城校区的独立社区插件，需运行在支持 HFP v2 协议的宿主应用中。插件可根据预设的阈值条件，使用校园卡余额为**宣城校区的常规电费、空调电费、校园网和洗浴**自动发起充值。

> [!CAUTION]
> **真实扣款与 Beta 试用风险声明**
> * **适用人群与扣款风险**：本插件触发后会实际扣减校园卡余额。当前版本处于 Beta 测试阶段，仅建议具备相应技术能力、理解触发逻辑、能够自行核对校方账单并愿意承担试用风险的用户安装。
> * **核账与暂停机制**：启用规则前，请逐项核对绑定的房间、手机号、充值金额及各项余额阈值。若出现「充值结果未确认」状态，插件将自动暂停后续充值任务；**请务必先查询校方账单核实是否已扣款或到账**，确认无误后再决定是否解除暂停。软件按「现状」提供，使用及核账责任以适用法律为准。

## 触发逻辑与调度规则

本插件**仅支持宣城校区**的常规电费、空调电费、洗浴及校园网充值。各项规则相互独立，每次调度检查时需**同时满足以下两项余额条件**，且通过宿主的可用余额核对与支付限制校验后，才会执行扣款：

1. **目标项目余额低于设定阈值**：例如宿舍电费或网费余额低于设定的触发线。
2. **充值前的校园卡总余额（实际余额加上待圈存金额）高于设定阈值**。提交前还会确认总余额足够支付本次充值；待圈存金额为负数时，会相应扣减可用总余额。

**后台调度与异常处理机制**：

* **检查周期**：依托宿主定时任务，约每 15 分钟执行一次状态检查。
* **可执行时段**：常规电费与空调电费仅在**北京时间 06:00 至 23:00 前**执行自动充值；洗浴与校园网支持全天检查。
* **失败冷却与未确认暂停**：若充值请求明确返回失败，同一项目至少等待 1 小时后才会再次尝试；若充值结果返回「未确认」，宿主会暂停后续自动充值，需人工核对账单并处理后方可恢复。

## 安装、配置与停用

1. **宿主环境准备**：确认手机端宿主应用支持 HFP v2、校园费用充值权限及后台定时任务。请先在宿主应用中完成宣城校区宿舍或洗浴手机号的绑定，并在宿主的充值设置中保存支付密码。
2. **导入插件**：正式发布后从 [Releases](../../releases) 下载 `.hfp` 插件包，在宿主的插件管理页面选择从文件导入，核对声明的权限列表后确认安装。
3. **配置并启用规则**：从插件设置页或对应费用详情页的「更多服务」进入配置界面。设置「余额阈值」「每次充值金额」与「校园卡余额阈值」，核对规则预览无误后启用。若后续更换了绑定房间/账号，或插件升级了规则数据格式，需重新确认授权。
4. **停用规则与核账处理**：如需停用某项自动充值，直接关闭对应项目的规则开关即可。若界面提示「充值结果未确认」，请按页面指引先核对校方账单，再进行后续操作。

## 源码打包与发版

本地打包需安装 Node.js 22.2 或更高版本。仓库包含完整的插件源码与打包脚本，可执行以下命令生成 HFP 包：

```sh
node scripts/pack.mjs --source hfp --key /path/to/private.pem --cert /path/to/certificate.pem
```

构建产物输出至 `dist` 目录。请注意：**覆盖升级已有版本必须使用原发布证书进行签名**；若使用自定义证书重新打包，插件导入后能否调用宿主的扣款接口，取决于宿主应用的安全信任策略。

1. 更新 `hfp/manifest.json` 中的 `version` 与 `revision` 并提交改动。
2. 在 [Actions](../../actions/workflows/build-plugin.yml) 中手动运行 `signed_candidate`，先行验证签名完整性与覆盖安装流程。
3. 审核通过后，在本地 `main` 分支对目标提交打标签并推送（以 `v1.5.0-beta.4` 为例）：

```sh
git tag -a v1.5.0-beta.4 -m "Release v1.5.0-beta.4"
git push --atomic origin main refs/tags/v1.5.0-beta.4
```

仓库公开后，版本标签构建将在验签通过后把 HFP 安装包与校验文件发布至 [Releases](../../releases)。带有 `-beta` 后缀的版本号将自动标记为预发行版本（Pre-release）。
